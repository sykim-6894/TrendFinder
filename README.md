# TrendFinder

포털 검색어·X(트위터)·유튜브·커뮤니티 인기글·뉴스 순위를 모아 일간·주간·월간 트렌드와 급상승 이슈를 보여 주는 정적 웹페이지. GitHub Actions가 2시간마다 데이터를 갱신하고(연령대별 자료는 하루 두 번) GitHub Pages로 배포합니다. API 키·서버 불필요.

## 구성

| 경로 | 역할 |
| --- | --- |
| `scripts/sources.mjs` | 소스별 수집기 (Node 22+, 의존성 없음) |
| `scripts/update.mjs` | 수집 → 카테고리 분류 → 통합 이슈·급상승·기간별 집계 → `public/data/trends.json` |
| `public/` | 배포되는 사이트 (`index.html`, `app.js`, `style.css`) |
| `data/history.json` | 최근 35일 순위 기록 — 주간·월간 집계와 급상승 계산용 |
| `.github/workflows/update.yml` | 2시간마다 수집 → 커밋 → Pages 배포 |

## 수집처

| 구분 | 소스 |
| --- | --- |
| 포털·검색 | 구글 트렌드(급상승 검색어), 네이트 실시간 이슈 |
| 뉴스 | 네이버 언론사별 많이 본 뉴스 |
| SNS·영상 | X 트렌드(trends24.in 경유), 유튜브 인기 뮤직비디오, 유튜브 인기 급상승(`YT_API_KEY` 가 있을 때만) |
| 커뮤니티 | 더쿠 HOT, 디시 실시간 베스트, 에펨코리아 포텐, 루리웹 베스트, 인스티즈 인기글, 네이트판 랭킹 |
| 연령대별 | 네이버 데이터랩 쇼핑인사이트 (10대~60대 인기 검색어) |

- **인스타그램·틱톡·스레드**는 인기 순위를 공개하지 않아(로그인·비공개 API 필요) 수집하지 않습니다.
- **네이버·다음**은 실시간 검색어를 폐지해, 네이버는 많이 본 뉴스로 대신합니다.
- 한 소스가 실패해도 나머지로 계속 진행하며, 실패한 곳은 페이지 아래에 표시됩니다. 일부 커뮤니티는 해외·클라우드 IP를 막을 수 있습니다.

## 계산 방식

- **통합**: 검색어형 소스(구글·네이트·X)의 키워드를 뼈대로, 단어가 겹치는 키워드와 그 단어가 제목에 들어 있는 글·기사를 한 이슈로 묶습니다. 점수 = 소스 가중치 × 순위 점수의 합 × (1 + 0.35 × (등장 사이트 수 − 1)).
- **주간·월간**: 매일의 순위 기록을 7일·30일 범위에서 합산합니다. 기록이 쌓이기 전에는 쌓인 날만큼만 반영됩니다. (연령대별은 데이터랩이 기간별 자료를 직접 제공)
- **급상승**: 직전 수집 대비 신규 진입·순위 상승, 소스가 표시한 NEW/상승, 구글 검색량, 여러 사이트 동시 등장을 더한 점수.
- **카테고리**: 제목의 단어 사전으로 어림 분류합니다 (`update.mjs` 의 `RULES`).

## 로컬 실행

```bash
node scripts/update.mjs
```

```bash
npx serve public
```

## 배포

1. GitHub에 **public** 저장소를 만들고 push
2. 저장소 Settings → Pages → Source를 **GitHub Actions**로 설정
3. Actions 탭에서 `Update data & deploy`를 한 번 수동 실행 (이후 2시간마다 자동)
4. (선택) 유튜브 전체 인기 급상승 영상을 넣으려면 YouTube Data API 키를 저장소 Secret `YT_API_KEY` 로 등록

각 사이트와 제휴 관계가 없는 비공식 프로젝트입니다.
